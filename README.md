# 💼 F5 Project & Team Control

**F5 Project & Team Control** — это современный, быстрый и легковесный **open-source аналог Jira**, созданный для управления проектами, задачами, командной разработкой и продуктивностью сотрудников. 

Платформа объединяет в себе гибкий трекер задач, **бесшовную интеграцию с GitLab**, **платформу расширений в духе Atlassian Connect**, автоматизированный процесс перекрестного код-ревью, кадровую матрицу компетенций и аналитику эффективности работы в реальном времени.

---

## 🌟 Основные возможности платформы

### 🎯 1. Управление проектами и командами (Jira-подобный трекер)
* **Создание и ведение проектов**: разделение по целям, контроль дедлайнов, назначение проектных менеджеров и владельцев.
* **Формирование проектных команд**: гибкое добавление специалистов на проекты с разделением зон ответственности.
* **Мониторинг прогресса**: процент готовности проектов, автоматическая оценка рисков и вероятности срыва сроков.

---

### 📋 2. Интерактивная Канбан-доска задач
* **Жизненный цикл задач**: наглядное движение карточек от постановки и работы над задачей до этапа код-ревью и финального завершения.
* **Приоритеты и дедлайны**: гибкая градация по важности и срочности, контроль дедлайнов и учет просроченной работы.
* **История и обсуждения**: подробный журнал всех изменений карточки задачи и встроенный блок комментариев.
* **Real-time синхронизация**: мгновенное обновление состояния доски для всей команды через WebSockets без необходимости перезагрузки страницы.

---

### 🦊 3. Интеграция с GitLab (GitLab CI/CD & Merge Requests)
* **Привязка коммитов и веток**: автоматическая связь веток, коммитов и Merge Requests с задачами по ключу вида `F5-42` в имени ветки, заголовке MR или сообщении коммита.
* **Авто-переход по событиям GitLab**: пуш в ветку задачи переводит её в работу, создание Merge Request автоматически отправляет задачу на код-ревью с назначением ревьюеров.
* **Статусы пайплайнов**: состояние сборки GitLab CI приходит вебхуком, отображается на канбан-доске и в карточке задачи, обновляясь в реальном времени через WebSocket.
* **Автоматическое закрытие**: при вливании (Merge) ветки задача закрывается — но только если оба назначенных ревьюера подтвердили изменения, иначе она остаётся на ревью с уведомлением исполнителю.
* **Действия из интерфейса**: создание ветки по задаче и перезапуск упавшего пайплайна прямо из карточки.

#### Настройка интеграции
1. В GitLab создайте Access Token с областью `api` (Settings → Access Tokens).
2. В F5 откройте проект → вкладка **Настройки** → блок **Интеграция с GitLab**: укажите адрес инстанса, числовой ID проекта, токен и основную ветку, затем сохраните и нажмите «Проверить подключение».
3. Скопируйте оттуда **URL вебхука** и **Secret token** и добавьте вебхук в GitLab (Settings → Webhooks) с триггерами `Push events`, `Merge request events`, `Pipeline events`, `Comments`.

Входящие вебхуки принимаются мгновенно и складываются в таблицу-инбокс, обработка идёт фоновым воркером с ретраями и защитой от дублей по `X-Gitlab-Event-UUID`; токен доступа хранится в БД в зашифрованном виде (AES-GCM) и наружу не отдаётся.

### 🧩 4. Платформа расширений (аналог Atlassian Connect)
* **Реестр приложений**: сторонние сервисы регистрируются в системе по манифесту — ключ, название, базовый URL, секрет, точки встраивания и список событий, на которые они подписаны.
* **Встраивание интерфейса через iframe**: если у активного расширения объявлена панель задачи, она отображается прямо в карточке; если объявлена вкладка проекта — она появляется в проекте динамически. Фронтенд ничего не знает о логике расширения, только рендерит `<iframe>`.
* **Событийные вебхуки**: при создании задачи, смене статуса и добавлении комментария подписанные расширения получают асинхронное HTTP-уведомление с HMAC-подписью тела (`X-F5-Signature`) — без блокировки пользователя.
* **Entity Properties API**: расширения хранят и читают произвольный JSON, привязанный к задаче (`/api/v1/extensions/properties/tasks/{id}/{key}`), не затрагивая структуру основной таблицы задач.

#### Как это устроено
Каждое событие задачи (`task.event.*`) уже публикуется в RabbitMQ через существующий Transactional Outbox — платформа расширений добавляет свою очередь (`business.extensions.dispatch`), забинженную на те же события, и рассылает вебхуки установленным на проект и включённым расширениям. Секреты расширений хранятся зашифрованными (тем же AES-GCM механизмом, что и токены GitLab).

#### Демонстрационный плагин
В `cmd/demo-extension` — самостоятельный сервис (без зависимостей на внутренние пакеты F5), эмулирующий стороннее приложение: чеклист в панели задачи, журнал полученных вебхуков во вкладке проекта, чтение/запись через Entity Properties API.

```bash
make run-demo-extension   # поднимет демо на :8090
```

Зарегистрируйте его в F5 (роль admin/director):
```bash
curl -X POST http://localhost:8080/api/v1/extensions   -H "Authorization: Bearer <JWT>" -H "Content-Type: application/json"   -d '{
    "key": "demo-timer",
    "name": "Демо-чеклист",
    "base_url": "http://localhost:8090",
    "shared_secret": "demo-secret-change-me",
    "task_panel_url": "/panel",
    "project_tab_url": "/tab",
    "project_tab_label": "Демо-плагин",
    "events": ["task_created", "task_status_changed", "task_comment_added"]
  }'
```

Затем включите его на нужном проекте во вкладке **Настройки** → **Расширения** — появится вкладка «Демо-плагин» и панель в каждой карточке задачи.

### 🔍 5. Автоматизированный флоу Код-ревью (Peer-Review)
* **Автоматический выбор ревьюеров**: при передаче задачи на проверку система назначает двух независимых участников проекта (исключая автора).
* **Система консенсуса**: задача закрывается только после получения подтверждения от обоих назначенных специалистов.
* **Уведомления**: мгновенные оповещения в реальном времени о назначении на проверку и о принятии изменений.

---

### 📊 6. Аналитический центр и статистика эффективности
* **Дашборд руководителя**: сводная статистика по компании — общее число проектов, распределение задач, процент закрытия вовремя.
* **Мониторинг рисков**: автоматическое выявление проектов с угрозой срыва сроков и большим числом просроченных задач.
* **Рейтинг сотрудников (Leaderboard)**: расчет индивидуальной эффективности с учетом сложности и приоритетов выполненных задач.
* **Тренды продуктивности**: наглядные графики динамики выполнения задач по дням и неделям.

---

### 🏢 7. Кадровый учет и матрица компетенций (HR-модуль)
* **Профили сотрудников**: контактные данные, должности, даты найма, статусы активности.
* **Организационная структура**: справочники отделов, департаментов и должностей компании.
* **Матрица навыков (Skills Matrix)**: учет стека технологий и ключевых компетенций каждого специалиста.
* **Ролевая модель доступа**: разграничение прав и уровней доступа внутри системы.

## 🛠️ Кратко о технологиях

* **Backend**: Высокопроизводительные микросервисы на **Go** с параллельной обработкой данных и Transactional Outbox.
* **Брокер сообщений**: **RabbitMQ** (надежная асинхронная доставка событий и интеграций).
* **База данных**: **PostgreSQL** (изолированные хранилища данных).
* **Frontend**: **React 19**, **TypeScript**, **Vite**, **Tailwind CSS**.
* **Инфраструктура**: **Docker & Docker Compose**.

## 🚀 Быстрый запуск

### 1. Запуск окружения (БД и брокер сообщений)
```bash
make docker-up
```

### 2. Переменные окружения (опционально)

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GITLAB_TOKEN_KEY` | значение `JWT_SECRET` | ключ шифрования access-токенов GitLab и секретов расширений |
| `PUBLIC_BASE_URL` | `http://localhost:8080` | внешний адрес шлюза, из него собирается URL вебхука GitLab |

### 3. Запуск сервисов бэкенда
```bash
# Запуск сервиса сотрудников и доступа (порт :8081)
make run-employee

# Запуск сервиса проектов, задач и аналитики (порт :8082)
make run-business

# Запуск шлюза API (порт :8080)
make run-gateway
```

### 4. Запуск пользовательского интерфейса
```bash
cd frontend
npm install
npm run dev
```
Интерфейс откроется по адресу: **`http://localhost:5173`**.
